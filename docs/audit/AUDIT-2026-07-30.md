# ba-mission-control — Consolidated Audit (2026-07-30)

**Commit:** `90d1c1a` · **Version:** `@bluearch/mission-control@1.1.1`
**Scope:** three parallel, findings-only reviews — Security, Efficiency/Performance,
and Deployment & Consumption (the customer journey from download → first run).
**No code was changed.** This is a triage document.

**Trust model (single-user, local):** no network-listening component. Untrusted
surfaces are `CLAUDE_BIN`, on-disk config, and repo-controlled files in each
session's `cwd` (a cloned/untrusted repo can ship hostile files).

## How this maps to the stabilization gate

The gate is: **status correctness · OOM leak · easy install** all green before
net-new features. This audit feeds two of the three directly:

- **OOM leak** → Efficiency §1: `TERM_SCROLLBACK=5000` (~320 MB baseline at 10
  slots) is the prime ceiling driver; `costStore.weeks/days` and
  `subagentUsageTailer.settled` are the two genuinely-unbounded structures and
  are **not** tracked by `heapProbe.fleetCounts`.
- **Easy install** → Deployment §2/§6: Linux triggers a node-gyp source compile
  (no Linux prebuild); npm-registry + Homebrew paths are advertised but not live.

## 1. Security

**Bottom line: no Critical or High.** All subprocess spawns are argv-form — no
`shell:true`, no `execSync`, no string `exec()`. Path derivation is UUID/regex
guarded. Two Medium, three Low.

### MEDIUM — Indirect prompt injection via repo-controlled `.mc/MEMORY.md` (plugin default ON)
- `tui/App.jsx:1560-1564` (inject), `tui/lib/projectMemory.js:35-44` (read),
  `tui/lib/plugins.js:35-40` (`plugin_projectMemory` `default: true`).
- On launch, mc reads `<cwd>/.mc/MEMORY.md` and **prepends its raw contents to
  the user's first prompt** to the agent. A cloned/untrusted repo can ship a
  crafted file whose text becomes injected instructions — to an agent that may
  be in `acceptEdits` or `bypassPermissions`. A toast reports the byte count but
  not the content.
- **Fix:** default `plugin_projectMemory` to `false`, or show/confirm the
  injected body for a not-yet-trusted repo before prepending.

### MEDIUM — OSC 52 clipboard escape forwarded from *background* agents (ungated)
- `server/ptyAgent.mjs:369-372`. The OSC 52 (set-clipboard) handler does
  `process.stdout.write` for **every** agent, "regardless of whether a zoom view
  is mounted." A background agent that emits an OSC 52 sequence (e.g. a tool
  cat'ing a malicious file) silently **overwrites the user's system clipboard**
  with attacker-controlled base64 on terminals that honor clipboard-write
  (iTerm2, kitty). The adjacent BEL handler (`:380-383`) was already gated on
  `this.zoomAttached` after the same class of bug; OSC 52 was missed.
- **Fix:** gate the OSC 52 forward on `this.zoomAttached`, exactly like the bell.

### LOW — Keystroke logger captures secrets verbatim
- `tui/lib/debugKeys.js:75-90`, wired in `tui/lib/TextField.jsx`. With logging on
  (`MC_DEBUG_KEYS=1` / `:debug-keys`), every keystroke incl. raw bytes is appended
  cleartext to `~/.config/claude-mc/debug-keys.log` — including the `:slack <url>`
  webhook the settings UI deliberately hides. Opt-in + local → Low.
- **Fix:** never log the `:slack` argument; redact `inputBytes` in command-bar contexts.

### LOW — Parsed transcript `permissionMode` set as spawn arg without whitelist
- `server/jsonlConnector.mjs:481-486` → `agent.mjs:290`, `ptyAgent.mjs:323`,
  `zoomSession.mjs:128`. `agent.permissionMode = ev.permissionMode` from parsed
  JSONL, no check against `PERMISSION_MODES`, then passed to the next respawn. Not
  injection (argv-form) and same trust boundary as the user (UUID-guarded home
  file), but a corrupt transcript could silently flip a respawn to
  `bypassPermissions`.
- **Fix:** validate `ev.permissionMode ∈ PERMISSION_MODES` before assigning.

### LOW — Hook command string interpolates install path; `"..."` doesn't neutralize `$(...)`
- `server/hookSettings.mjs:21`, injected at `ptyAgent.mjs:331-332`. String handed
  to `claude --settings` and run **through a shell** by claude's hook runner.
  Paths are local (node bin + install dir), but an install dir containing
  `$(...)`/backticks would execute. The existing `TODO(hook-inject)` only
  anticipates spaces.
- **Fix:** argv-array command form if the hook schema allows; else escape shell
  metacharacters, not just spaces.

### Checked & CLEAN
All spawn sites argv-form (agent/ptyAgent/zoomSession/shellSession/git/tasks/
modelProbe/auth/version/main); shell `cd` is POSIX single-quote escaped; path
traversal neutralized by UUID-shape guards + `encodeCwd`; all `JSON.parse` in
try/catch feeding display not eval/path/spawn; `gh` output argv+JSON+timeout
guarded; card/log text stripped of OSC/CSI/C0 via `format.humanize` (note: this
does **not** cover the raw PTY passthrough in MEDIUM-2); Slack secret hidden +
never logged; `:mcp` reads config but only enumerates names, never executes;
no new third-party deps in the working tree.

## 2. Efficiency / Performance

Default agent path is **PtyAgent** (`fleet.mjs:31`), so PtyAgent + the three
tailers are the hot path. Many prior audit fixes verified still-in-place
(coalesced render, tail caps, costStore.lastSeen GC, throttled persist).

### HIGH — `sessionFileTailer.maybeRepoint` runs a full dir scan every 1.5 s per idle slot
- `server/sessionFileTailer.mjs:305-329,375-379,80-94`. Once a session's file
  hasn't grown for 3 polls (any idle / waiting-on-user slot), `findRotatedSession`
  does `readdir(projectDir)` + `fsp.stat()` on **every** UUID `*.jsonl` newer than
  the floor — **on every subsequent 1.5 s poll** (project dirs can hold 1600+
  files). Biggest idle CPU/disk drain found.
- **Fix:** back off the rotation hunt after the first miss (like
  `subagentUsageTailer`'s `ABSENT_BACKOFF`), or cache readdir + re-scan on dir-mtime.

### HIGH — Three always-on 1.5 s stat-poll timers per agent; only one backs off
- `sessionFileTailer.mjs:375`, `statusHookTailer.mjs:86`, `subagentUsageTailer.mjs:201`.
  Baseline for 10 idle slots ≈ 30-40 `stat` syscalls/sec doing nothing.
- **Fix:** idle-down `sessionFileTailer`/`statusHookTailer` cadence (fs.watch stays
  the fast path; poll is a cloud-sync backstop).

### HIGH — Slow-clock tick re-snapshots every ~300 ms independent of the change subscription
- `tui/App.jsx:190-210`. While any agent is active, `tick()` calls
  `fleet.snapshot()` + `setSnapshot()` ~3×/s on top of event-driven repaints; each
  new `snapshot` re-fires four `[snapshot]` effects (costStore, session-sync,
  stuck, ctx) and re-derives `fleetLog`/`fleetTpm`.
- **Fix:** the tick only needs to advance derived *time* (`stuckMin`); bump a
  light `now` clock and let the change-subscription own snapshot production.

### MEDIUM
- **`TERM_SCROLLBACK=5000` is the largest heap baseline (~32 MB/slot → ~320 MB @10)**
  — `ptyAgent.mjs:52`. Bounded, not a leak, but the likely OOM-ceiling driver.
  **Fix:** lower to ~2000 or make it a setting; trim scrollback for non-zoomed slots.
- **`costStore.weeks` / `costStore.days` grow unbounded** — `tui/lib/costStore.js:117-129`.
  `gc()` only prunes `lastSeen`; one key/week + one key/day accrue forever and
  re-serialize to `costs-week.json` on every dirty write. **Fix:** prune old
  `days`/`weeks` in `gc()`.
- **`subagentUsageTailer.settled` Set grows within a session** — `subagentUsageTailer.mjs:78`.
  One entry per completed sub-agent file, reset only on SID rotation. Heavy fan-out
  with no `/clear` leaks filenames. Acknowledged/deferred to task 0350.
- **`PtyAgent.toJSON()` runs bounded term-buffer scans + allocs per snapshot per agent**
  — `ptyAgent.mjs:883-1021`. **Fix:** memoize scan results keyed on `lastPtyTs`.
- **Idle fleet still mints a full re-render every 3 s** — `App.jsx:206`. **Fix:**
  skip `setSnapshot` on idle ticks unless a derived threshold changed.
- **`syncFromSnapshot` re-reads+parses whole `sessions.json` every 2 s while active**
  — `tui/lib/sessionStore.js:170`. **Fix:** keep the store in memory (like CostStore).

### LOW
`deriveFleetLog` sorts every frame (`FleetLog.jsx:45-62`); terminal retained
during PTY-exit backoff (`ptyAgent.mjs:463-470`); per-agent `change` listener not
explicitly `.off()`'d on kill (`fleet.mjs:99`, no leak as written); plan-usage
poller fixed at 8 s even when empty.

### Heap-probe gap
`heapProbe.fleetCounts` tracks `termLines/pendingSub/usageByMsg/tail` but **not**
`costStore.weeks/days` nor `subagentUsageTailer.settled` — the two real
unbounded-growth candidates. **Add both** so the OOM watchdog NDJSON catches
genuine growth vs the fixed ~320 MB term baseline.

## 3. Deployment & Consumption (customer journey)

**Bottom line:** from-source and `github:` installs work today; packaging hygiene
is genuinely good (complete `files` whitelist verified via `npm pack` = 75 files,
runtime node-pty self-heal, friendly crash-bail, honest preflight banner). Sharp
edges are in the ecosystem around mc, not mc's own code.

### HIGH — Linux (a supported platform) triggers a node-gyp source compile
- node-pty `1.1.0` prebuilds cover only darwin/win — **no `linux-*`**. Its install
  is `node scripts/prebuild.js || node-gyp rebuild`, and `prebuild.js` is
  local-only (no network fallback), so on Linux the `||` compiles from source,
  needing python3 + make + a C++ toolchain. README lists Linux as supported but
  never warns. Lean-box users hit a cryptic node-gyp failure at install.
- **Fix:** bump node-pty to a version shipping Linux prebuilds, or document
  `build-essential`+`python3` next to Requirements.

### MEDIUM
- **Registry + Homebrew advertised but not published/functional.** Quick Start's
  working path is `npx github:xxyjoel/ba-mission-control`, but the npm version
  badge and `npm view` guidance imply a published `@bluearch/mission-control`
  (it 404s). Mixed signals. **Fix:** gate the badge/instructions behind actual
  publish, or lead unambiguously with the `github:` path.
- **Homebrew formula is copy-paste-broken** — `packaging/homebrew/mission-control.rb`
  pins the `1.0.0` tarball (pkg is `1.1.1`) with a literal
  `REPLACE_WITH_TARBALL_SHA256...` placeholder. Blocked on the same unpublished gap.
- **No uninstall/cleanup docs anywhere.** User must know to global-remove **and**
  `rm -rf ~/.config/claude-mc/` + `~/.local/state/claude-mc/` (transcripts orphan
  and grow). **Fix:** add a 3-line Uninstall section.
- **Auth probe depends on exact `claude auth status` JSON.** A different claude CLI
  version can make `auth.js` fall back to `ANTHROPIC_API_KEY` detection and print a
  scary "NOT LOGGED IN" to an OAuth user who *is* signed in. (Can't verify the
  external CLI surface from this repo.) **Fix:** validate against pinned claude 2.x;
  soften wording.
- **Failed New-Session (no `claude` on PATH) surfaces only in the per-session tail.**
  Boot warns but doesn't block; a user who skips the banner sees a session
  silently die. **Fix:** toast the launch-failure reason.
- **`:where` + data footprint undocumented in README.** The in-app `:where` exists
  (`App.jsx:1095`) but isn't in the README; config/state paths are scattered.
  **Fix:** add a "Where mc keeps your data" table + mention `:where`.

### LOW
Shipped `<!-- TODO(release) -->` comment + a bare `https://github.com/` placeholder
link in README; README is 914 lines with install split across 4+ locations.

### Already solid (no action)
`files` whitelist complete (no clone-vs-registry drift); node-pty exec-bit
self-heal at postinstall **and** runtime (covers npx-skips-postinstall); `!`-shell
resolves `$SHELL` with fallbacks (no zsh hardcode — `shellSession.mjs:127`);
crash-bail restores terminal + points at issues; `prepublish-guard` enforces
clean-tagged-tree publish; preflight banner gives honest first-run status; Session
Health dependency **degrades gracefully** (health dot omitted when
`.project-health` data absent — never hard-required).
